# Forms Loom does not read

Loom reads your source without running it, so a dispatch or a registration it recognises can still name something only the running app knows. Each one is listed in `unresolved_dispatches` with the expression, its file and line, and a `reason`. The reason names the shape of the code, and each one below has a single change that makes the form readable.

The sections group the reasons by what Loom was reading. To find yours, scan for the line you wrote, or look the `reason` up from the index. [Why was my code missed](../guides/why-was-my-code-missed.md) starts from the symptom instead, and [What Loom detects](what-loom-detects.md) lists what each scanner does read.

## Dispatch targets

The call is recognised as a dispatch, but the event, job, mailable or notification it names is not a class Loom can read at that line.

### `dynamic_class_name`

The target is a variable, or `new $class` / `$class::dispatch()`.

```php
event($event);
```

**Fix:** Pass `new OrderPlaced(...)` or `OrderPlaced::class` at the call. A variable the method assigns once with `new X` or `X::class` is followed.

```php
$class::dispatch($id);
```

**Fix:** Call the class itself: `ProcessOrder::dispatch($id)`.

### `container_resolution`

The target comes from `app()`, `resolve()` or `->make()`.

```php
use App\Events\OrderPlaced;

event(app(OrderPlaced::class));
```

**Fix:** Construct the event with `new`.

### `string_concatenation`

The target is built by concatenation or interpolation.

```php
event('App\Events\\'.$name);
```

**Fix:** Use a `::class` reference.

### `conditional_dispatch`

A ternary or `match` whose branches cannot be evaluated.

```php
use App\Events\OrderEscalated;

event($urgent ? new OrderEscalated : $fallback);
```

**Fix:** Make both branches `new X`, which Loom records, or split into two `if` branches that each dispatch one class.

### `dynamic_list`

A list of dispatch targets built at runtime (a variable, a spread, a collection).

```php
Bus::chain($jobs)->dispatch();
```

**Fix:** Write the list as an array literal of `new X` items. A list the method assigns once is followed.

```php
use App\Jobs\Prepare;

Bus::chain([new Prepare, ...$jobs])->dispatch();
```

**Fix:** Spell every job out in the literal; the `new X` items beside the spread are still read.

### `string_event_name`

The event is a string literal such as `'service.installed'`, not a class.

```php
event('service.installed');
```

**Fix:** Fire an event class, `event(new ServiceInstalled(...))`. Loom indexes class events, so a string name is not linked to anything.

### `closure_job`

A closure is dispatched as a job, so no class names it.

```php
dispatch(function () { /* ... */ });
```

**Fix:** Move the work into a job class and dispatch `new SyncInventory(...)`.

### `view_mail`

A mail sent from a view name or array and a closure, so there is no mailable class.

```php
Mail::send('emails.welcome', $data, fn ($message) => $message->to($user));
```

**Fix:** Send a mailable: `Mail::to($user)->send(new Welcome($data))`.

### `call_result`

The target is what a method, static or function call returns.

```php
event($this->makeEvent());
```

**Fix:** Construct the event where it is dispatched: `event(new OrderPlaced(...))`.

### `stored_target`

The target is read from a property, an array element or a constant.

```php
event($this->event);
```

**Fix:** Construct the event where it is dispatched: `event(new OrderPlaced(...))`.

### `relative_class_name`

`self`, `static` or `parent` in a trait or anonymous class, or `parent` with no parent: there is no class name to read.

```php
self::dispatch($id);
```

**Fix:** Name the class: `ProcessOrder::dispatch($id)`. In a trait, `self` is whichever class uses it, and Loom does not follow that.

### `unsupported_expression`

An expression form no other reason covers (a `??` coalesce, an anonymous class).

```php
use App\Events\OrderPlaced;

event($event ?? new OrderPlaced);
```

**Fix:** Dispatch a `new X` or `X::class` directly.

## Class lookup

The class is named, but the index has nothing to link to. A dispatch gets one of these, never both.

### `class_not_found`

The target is a class name, but no file declaring it exists in the scanned directories (a vendor class, a missing file, an excluded path); `expression` is `Fqcn::class`.

```php
use Illuminate\Auth\Events\Registered;

event(new Registered($user));
```

**Fix:** Nothing to fix for a package class. For one of your own, add its directory to `scan.paths` or correct the name.

### `target_not_indexed`

A class file was found, but it is not an indexed event, job, mailable or notification.

```php
use App\Support\StartLogDrain;

StartLogDrain::dispatch();
```

**Fix:** Make the class a job (`ShouldQueue`, or place it under `Jobs/`) or an event so it gets a row.

## Listener registrations

The registration is recognised, but its event or handler cannot be read from the source.

### `unreadable_event_name`

A registration whose event name or key is not a `::class` reference or a literal Loom can read (a variable, a call, an `eloquent.*` name with an unknown hook).

```php
use App\Listeners\SendReceipt;

Event::listen($name, SendReceipt::class);
```

**Fix:** Register against `OrderPlaced::class` or a string literal.

### `untyped_closure_listener`

An `Event::listen(function ($e) {...})` closure whose first parameter has no event class type.

```php
Event::listen(function ($event) { /* ... */ });
```

**Fix:** Type the first parameter with the event class: `function (OrderPlaced $event)`.

### `unreadable_listener`

A listener registration (`$listen`, `Event::listen()`, a subscriber return array) whose handler is not a class reference, a `[Class, method]` tuple, a readable string or a closure.

```php
use App\Events\OrderPlaced;

Event::listen(OrderPlaced::class, $listener);
```

**Fix:** Pass `SendReceipt::class`, a `[SendReceipt::class, 'handle']` tuple or a closure.

### `unreadable_subscriber`

An `Event::subscribe()` call or `$subscribe` entry that is not a `::class` reference, a string literal or `new`.

```php
Event::subscribe($subscriber);
```

**Fix:** Pass `OrderSubscriber::class`.

## Model hooks

The hook is recognised, but its callback or model cannot be read.

### `unreadable_model_hook`

A `static::creating(...)` style hook whose callback is not a closure or readable callable.

```php
static::creating($callback);
```

**Fix:** Pass a closure, or a `[Handler::class, 'method']` callable.
