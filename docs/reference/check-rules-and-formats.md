# Check rules and output formats

The rules, exit codes and output formats of `loom:check` and `loom:diff`; the walkthrough is [Gate your CI](../guides/gate-your-ci.md).

```bash
php artisan loom:check storage/loom/index.json --baseline=.loom/baseline.json --format=json
php artisan loom:diff .loom/baseline.json storage/loom/index.json --format=markdown
```

Both read finished index files and need no source tree. Arguments and options are in [Commands](commands.md#loomcheck); in `loom:diff`, entries only in `new` are added and entries only in `old` are removed.

## Rules

| Key | Fails when | What to do |
| --- | --- | --- |
| `schema` | The index doesn't validate against the Loom schema. | Re-run `loom:scan`. |
| `orphan-listeners` | A listener handles no events. | Type-hint the event on `handle()`, register the listener, or delete it. |
| `orphan-events` | An event is never dispatched and never handled. | Delete it, or add the dispatch or listener that was meant to exist. |
| `unresolved-dispatches` | See below. | Make the dispatched class a literal class name, or accept it into the baseline. |
| `cyclic-dispatch` | A chain of dispatches loops back to its start. | Break one link in the reported chain. |

### Unresolved dispatches, baseline and strict

| Flags | Behaviour |
| --- | --- |
| Neither `--baseline` nor `--strict` | Passes without checking anything. |
| `--baseline=PATH` | Fails on any unresolved dispatch not in the baseline. |
| `--strict` | Fails on every unresolved dispatch, whatever the baseline says. |

Baseline entries match by file, line and expression, so moved code looks new; see the [recipe](../recipes/new-unresolved-dispatches.md).

### Cycle detection

`cyclic-dispatch` draws an edge from each event or job to what its handlers dispatch, and reports one representative cycle per back-edge: fix it, re-run, and the next one surfaces.

## Exit codes

| Command | Code | Meaning | What to do |
| --- | --- | --- | --- |
| check | `0` | Every rule that ran passed. | Nothing. |
| check | `1` | A rule found a violation. | Fix it or change the policy. Fail the job. |
| check | `2` | Nothing was checked: bad path, invalid JSON, unknown `--format`, unknown `--skip` key. | Fix the invocation. Fail the job too. |
| diff | `0` | No semantic changes. | Nothing. |
| diff | `1` | Changes exist. Not an error. | Post the diff. Fail only if you want drift to block. |
| diff | `2` | A path isn't a file, the JSON is invalid, or `--format` is unknown. | Fix the invocation. |

## What the diff compares

`scanned_at`, `loom_version`, `laravel_version` and `stats` are ignored. Entries match by identity:

| Section | Matched by |
| --- | --- |
| events, listeners, jobs, mailables, notifications | `fqcn` |
| observers | `fqcn` and `observes` |
| model_events | `id` |
| scheduled_tasks | `file`, `line`, `kind`, `target` |
| unresolved_dispatches | `file`, `line`, `expression` |
| closure_listeners | `file`, `line`, `event`, `registration` |

Cross-link arrays such as `handled_by` and `dispatches` compare by membership: a member is added or removed, never edited.

Reordering `notifications.channels` counts as a change. Closure listeners are only added or removed.
