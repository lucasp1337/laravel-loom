# Schema

Reference for `storage/loom/index.json`. The authority is `schema/loom-index.schema.json`; the tables below are generated from it, descriptions included. To read an index from PHP, see the [PHP API](php-api.md).

- Every top-level field is required, empty arrays are valid and `null` is never valid for an array.
- The schema rejects unknown top-level keys; the PHP loader ignores them (see [Versioning](#versioning)).
- A trailing `?` on a field name marks it optional.
- `file` is a [relative, forward-slashed path](#relativepath) and `line` is 1-indexed.
- Lists that name dispatches or handlers (`dispatched_from`, `handled_by`, `dispatches`, `sent_from`, `notified_from`) are derived by joining sections after the scan. They are empty when nothing matches.

#### Call forms by `mode`

| `mode` | Call forms |
| --- | --- |
| `sync` | `X::dispatchSync()`, `dispatch_sync()`, `Bus::dispatchSync()`, `Bus::dispatchNow()`, `Mail::sendNow()`, `Notification::sendNow()`, `->notifyNow()` |
| `after_response` | `X::dispatchAfterResponse()`, `Bus::dispatchAfterResponse()`, `->afterResponse()` on a dispatch chain |
| `push` | `Queue::push/pushOn/later/laterOn/bulk()`, `Mail::queue/onQueue/queueOn/later/laterOn()` |
| omitted | `dispatch()`, `X::dispatch()`, `Mail::send()`, `Notification::send()`, `$user->notify()` |

`->afterResponse()` and `->afterResponse(true)` give `after_response`. `->afterResponse(false)` cancels an earlier `->afterResponse()` in the same chain, and a non-literal argument is ignored.

### `dispatch`

A resolved dispatch made from a class method or closure.

| Field | Type | Description |
| --- | --- | --- |
| `target` | string | FQCN of the dispatched event, job, mailable or notification. |
| `kind` | one of `event`, `job`, `mailable`, `notification` | Whether the target is an event, a job, a mailable or a notification. |
| `confidence` | one of `high`, `medium`, `low` | `high` for a target resolved in the handler method itself; `medium` when the call sits in a helper method the handler reaches (see `via`); `low` is reserved. |

| `line` | integer ≥ 1 | 1-indexed line of the dispatching call. |
| `via`? | array of string | Present when the call sits in a helper method of the same class that the handler reaches through `$this->`, `self::` or `static::` calls: the helper method names in call order, ending with the method that holds the call. Absent when the handler makes the call itself. |

## Determinism

Two scans of identical source produce byte-identical JSON except `scanned_at`. Files are read in sorted path order and every section is totally ordered by its natural key plus tie-breakers:

| Section | Order |
|---|---|
| `events`, `model_events` | `id` |
| `listeners`, `jobs`, `mailables`, `notifications` | `fqcn` |
| `observers` | `fqcn`, `observes` |
| `closure_listeners` | `event`, `file`, `line`, `end_line`, `registration` |
| `scheduled_tasks` | `file`, `line`, `kind`, `target`, `name`, `cron` |
| `routes` | `file`, `line`, `method`, `uri`, `name` |
| `unresolved_dispatches`, `unresolved_routes` | `file`, `line`, `expression`, `reason` |

Nested lists use the same rule: dispatch sites by `file`, `line`, `method`, `mode`; `dispatches[]` by `file`, `line`, `target`, `kind`; `handled_by[]` by `listener` (or `handler`), `method`; `handles[]` by `event`, `method`. Arrays whose source order is meaningful (`middleware`, `channels`, `arguments`) keep it. Paths are relative to the app root, so the output does not depend on where you scan from.

## Versioning

`schema_version` (`MAJOR.MINOR`) is the version of the document shape, and consumers key on it. The schema pins the major (`^1\.[0-9]+$`). `loom_version` is informational; nothing should branch on it.

| Change | Bump |
| --- | --- |
| New optional field, new enum value, new section; required field made optional | Minor |
| New required field; optional field made required | Major |
| Field renamed, retyped or removed; enum value or section removed | Major |
| Bug fix that doesn't change shape | None |

### Reader behaviour

`IndexLoader`, `loom:check` and `loom:diff` behave the same way:

- Same major, any minor: loads. Unknown keys are ignored.
- Missing `schema_version`, an older major or a newer major: refused with a message to re-run `php artisan loom:scan`. There is no migration; the index is a derived file.
- `loom:diff` refuses to compare two indexes with different majors and exits `2`.

`1.0` is the frozen baseline: every field name, enum value and nullability on this page, and the MCP tool names and inputs in [MCP tools](mcp-tools.md), follow the table above from here.

!!! warning "Validate with the producer's schema"
    The schema sets `additionalProperties: false`, so validating with a stored copy rejects a later minor. Validate with the schema shipped in the same release as the producer, or don't validate.

## Open enums

These enums grow in minor releases. Consumers must tolerate values they don't know and must not fail on them:

- `kind` on dispatch entries (`event`, `job` today)
- `registration` on listeners and observers
- `reason` on `unresolved_dispatches[]`
- `confidence`: only `high` is emitted today; `medium` and `low` are reserved, ordered `high > medium > low`
- `routes[].method`
- `model_events[].event` and `observers[].hooks[]`, which follow [Eloquent's model events](https://laravel.com/docs/12.x/eloquent#events)
- `scheduled_tasks[].kind` and `scheduled_tasks[].frequency.unit`

Removing or renaming a value is a major change; adding one is minor.

What to do about it:

- Pin the Loom version you build tooling against, and upgrade deliberately.
- Read the [changelog](https://github.com/lucasp1337/laravel-loom/blob/main/CHANGELOG.md) before upgrading; shape changes are listed there.
- Regenerate the index with `php artisan loom:scan` after every upgrade instead of reusing an old file.
