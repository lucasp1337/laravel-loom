# Ask an agent about your events

Register `loom:mcp` with your MCP client so an agent answers from the index instead of grepping your source.

```json
{
  "mcpServers": {
    "loom": {
      "command": "php",
      "args": ["/var/www/shop/artisan", "loom:mcp"]
    }
  }
}
```

Put that in your client's MCP config, such as `.mcp.json` at the project root, and restart the client. The server needs `laravel/mcp` (`composer require laravel/mcp --dev`). Use an absolute path to `artisan`; under Docker or Sail, run `php artisan loom:mcp` inside the container without a TTY.

## Where the index comes from

The server reads the index `loom:scan` wrote, at `index_path`, and reloads it when the file changes. With no flag it scans once, on the first tool call, if the file is missing. On a shared machine or in CI, make a missing index an error:

```bash
php artisan loom:mcp --no-scan
```

```text

<!-- /generated:output:mcp-no-scan -->

`--scan` scans before serving, `--no-scan` never scans and `--snapshot=PATH` serves another file; see [Commands](../reference/commands.md#loommcp). The server answers from your last scan, not your working tree, so rescan after you change code.

!!! warning "Keep stdout clean"
    Client and server talk JSON-RPC over stdout. A stray `echo`, a `dd()` or a PHP notice breaks the connection: log to a file and set `display_errors=stderr` for the CLI.

## What the agent can't see

A dispatch like `event($this->followUp)` names no class, so it is never a `target`. `find-unresolved-dispatches` lists these:

    "unresolved_dispatches": [

```

Check this list before you trust "nothing listens to X". Each dispatch carries a [`confidence`](../reference/schema.md#dispatchconfidence); chain responses report `truncated` when `depth` cut them short.
